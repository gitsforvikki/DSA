# 15. 3Sum

**Problem:** https://leetcode.com/problems/3sum/  
**Difficulty:** Medium  
**Status:** Solved independently  
**Pattern:** Sorting + Two Pointers

## Problem statement

Given an integer array, find all **unique triplets** `[a,b,c]` at distinct indices such that `a+b+c=0`. Return each triplet only once.

## My original JavaScript solution

```javascript
/**
 * @param {number[]} nums
 * @return {number[][]}
 */
var threeSum = function(arr) {
    arr.sort((a,b) => a-b);
    let ans = [];
    for(let i = 0; i < arr.length; i++){
        // i dont want to call this twoSum() for duplicate of arr[i]
        if(arr[i-1] != arr[i]) twoSum(arr , i , ans);
        
    }

    return ans;
};
function twoSum(arr, x , ans){
    let start = x + 1;
    let end = arr.length - 1;
   
   while(start < end){

     // calculate sum here
    let sum = arr[x] + arr[start] + arr[end];
    if(sum > 0) end--;
    else if(sum < 0) start++;
    else{
        //sum == 0
        ans.push([arr[x] , arr[start] , arr[end]]);
        start++;
        end--;
        // corner case--> if skip duplicate value for the arr[start]. and it will handle duplicate for arr[end] as well
        while(start < end && arr[start] == arr[start - 1]){
            start++;
        }
    } 

   }
}
```

## Step-by-step explanation

1. Sort numerically, so we can move pointers based on whether the sum is too large or too small.
2. Fix `arr[i]` as the first number. Skip repeated fixed values with `arr[i-1] != arr[i]` so the same first number is not processed again.
3. Run `twoSum(arr, i, ans)` over the suffix, using `start=i+1` and `end=arr.length-1`.
4. If `sum > 0`, decrease `end`; if `sum < 0`, increase `start`.
5. If `sum === 0`, save the triplet, move both pointers, then skip duplicate values at `start`.

### Why only skip duplicates on the left after a match?

With a fixed first number, after a matching pair is found, both pointers move. A repeated `start` value could produce the same triplet again, so we skip it. Skipping repeated `end` values as well is an optional, standard alternative; it is **not necessary for correctness** here because for a fixed first and second value, only one third value can complete zero.

## Dry run

Input: `[-1,0,1,2,-1,-4]`

Sorted: `[-4,-1,-1,0,1,2]`

## Complexity

- **Time: O(n²)**. Sorting costs O(n log n); for each fixed index, two pointers scan the remaining suffix in O(n).
- **Auxiliary space:** O(log n) typical sorting stack space, depending on JavaScript engine; two-pointer logic uses O(1) extra space. The result array is excluded.
- **Output space:** O(k) triplets, where k is the number of unique triplets.

## Edge cases and implementation notes

- Arrays with fewer than 3 values return `[]`.
- Repeated zeroes must produce exactly one `[0,0,0]`.
- Duplicate negative and positive numbers must not create duplicate triplets.
- Sorting **mutates the input array**. Copy first with `[...arr].sort(...)` if mutation is not allowed.
- `!=` works for numeric inputs, but `!==` is preferable for strict comparisons.
- Optional efficiency improvements: limit outer loop to `i < arr.length - 2`; stop early when `arr[i] > 0` since all later values are nonnegative.
